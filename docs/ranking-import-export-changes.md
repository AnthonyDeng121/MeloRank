# 榜单导入与导出改进记录

本次目标是修复播放队列清空、数字作者被误识别为分数、导入不加载封面、导出条目跨页分离，并补齐 PDF、图片和页面返回操作。

## 修改前后

| 问题 | 原行为 | 新行为 |
| --- | --- | --- |
| 清空队列 | 主要清除 React 列表，播放器和异步请求可能仍有活动 | 同步暂停音频、移除音源、重新加载媒体元素、重置进度和歌词；旧播放请求通过代次标记失效 |
| 导入评分 | 在作者字段任意位置查找第一个数字 | 只识别空格分隔且位于行尾的完整评分表达式 |
| 数字作者 | Kep1er、B1A4、16 等可能被截断 | 保留作者名，再解析真正的末尾分数 |
| 格式错误 | 错行可能静默跳过或部分导入 | 显示行号及错误原因，修正后再整批导入 |
| 封面 | 导入时只写占位图，编辑保存才触发查找 | 导入后自动匹配，最多三个任务并发，显示完成数和未匹配数 |
| 格式示例 | 两种格式像是两条顺序操作 | 增加“或者”“任选一种，也可混合”的说明 |
| DOCX | 标题和正文是独立可分页行；部分图片字节与扩展名不符 | 标题与正文嵌入同一个不可拆分的外层行；设置 A4、四边 720 twips（0.5 英寸）的窄页边距；图片统一为真实 PNG |
| PDF、图片 | 没有对应导出 | 从同一份 DOCX 解析页面，在独立 iframe 中逐页渲染，导出 PDF、裁掉页边距的分页 PNG ZIP 或拼接长 PNG |
| 返回 | 推荐页没有专门返回入口 | 记录应用内导航历史，在年度歌曲、年度专辑和艺人推荐页左上角返回上一页 |

## 可用于学习和报告的实现要点

- **文本解析应先定义边界**：作品和作者以第一个两侧带空格的横线分隔；评分必须占据行尾。避免把字段内部数字当成结构标记。使用纯函数解析便于用真实输入回归。
- **兼容 Unicode 空白**：统一换行、制表符、不换行空格等，保留原本的中日韩文字、标点和名称内连字符。
- **评分语法**：`原始分数+整体性++保值度`，加分可省略，原始分数为 0–100、加分为 0–2。评分模式也支持不带分数的条目；不评分模式完整保留作者字段，避免“作者名字本来以独立数字结尾”的歧义。
- **异步状态要能失效**：播放和封面请求通过代次标记避免旧响应恢复已清空的状态；封面写回还检查条目 ID、作品、作者和现有封面，避免覆盖用户编辑。
- **限制批处理并发**：三路封面任务避免一次导入 91 条数据时同时发出全部请求；请求设置超时，错误不阻塞其他条目。
- **分页以完整条目为单位**：显式规划页面，加上 OOXML `cantSplit`，把标题与主体放进同一个外层表格行。评分模式保持三列，不评分模式保持双列。
- **图片 MIME 与字节要一致**：不能将 SVG 或 WebP 原始字节标为 PNG。通过 Canvas 编码后再嵌入，解决 Word 图片损坏。
- **多格式导出共用来源**：DOCX 是 PDF 和图片的内容来源；隔离 iframe 中逐页渲染，排除应用 CSS、页面滚动和后续页面坐标对截图的干扰。

## 验证

- `npm run check:import`：使用用户提供的全部 91 条输入，检查数字作者、日期、Unicode 空白、标题连字符、加分及错误行。
- `npm run check:queue`：在播放 URL 请求尚未返回时清空队列，再返回旧响应，验证不会重新播放。
- `npm run check:export`：生成实际 DOCX 压缩包，检查评分和不评分分页、所有标题、窄页边距、不可拆行标记及 PNG 字节。
- `npm run check:ranking`、`npm run check:music`：保留原有保存、导入、编辑和专辑播放回归检查。
- 浏览器实测五条数据自动加载全部封面，包括 Kep1er、B1A4、16；实测播放 MAYHEM 后清空队列并归零；实测返回按钮。
- 实际导出并检查多页 PDF、分页 PNG、长 PNG 和不评分双列版式。

## 使用边界

旧导入已丢失的作者字符和原始分数无法从错误记录可靠还原，需要用原始文本重新导入。不会擅自覆盖浏览器中的历史榜单。

封面采用严格匹配；QQ 音乐没有收录或名称不同的项目会显示未匹配，可手动上传。并未添加或启动额外 QQ 音乐仓库，新 API 仍可按具体功能需求再接入。

PDF 和 PNG 使用浏览器 DOCX 渲染器生成，不需要上传文档或安装 Office。PDF 当前采用页面图像，不能直接选择其中的文字；Word/WPS 的字体替代及排版引擎可能带来细微差异，不承诺与任意 Office 环境逐像素一致。特别长的单条评论超出一页时会提示调整；长图过大时建议选择分页图片。

渲染器分页行为参考 [docx-preview 官方说明](https://github.com/VolodymyrBaydalka/docxjs#breaks)：它识别显式分页，不执行 Word 式实时重新分页，因此应用主动安排页面。
