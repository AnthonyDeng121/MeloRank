# 歌单回写

在“我的音乐 → 我创建的歌单 → 歌单详情 → 编辑歌单”操作。每次操作直接保存到当前音乐账号，不需要另点保存。

| 能力 | QQ 音乐 | 网易云音乐 |
| --- | --- | --- |
| 搜索并添加歌曲 | 支持 | 支持 |
| 从歌单移除歌曲 | 支持，需在页内确认 | 支持，需在页内确认 |
| 歌曲拖拽排序 | 已接入，实号待验收 | 已接入，实号待验收 |
| 自动刷新歌曲列表和数量 | 支持 | 支持 |
| 歌单名称／专辑封面选择 | 已接入，实号待验收 | 已接入，实号待验收 |
| 歌单另存年度单曲／专辑榜 | 支持 | 支持 |

仅允许编辑本人创建的普通歌单，喜欢的歌曲、收藏专辑、他人的歌单不开放编辑。Spotify 保持读取功能。

QQ 排序已按官方 Windows 客户端的 `SeqSonglist` 序列化参数接入，参数依据和实号验收限制见 [QQ 排序协议核对](qq-playlist-order.md)。最新的拖拽交互、歌单资料编辑和转榜单流程见 [两端歌单编辑与年度榜单](playlist-workflow.md)。本次不编辑歌单描述，也不上传任意本地图片。

## 保存过程

1. 请求携带当前账号凭据，不使用全局账号或回退本地登录态。
2. 后端重新读取歌单，验证当前账号是创建者，普通歌单目录可写且曲目读取完整。
3. 对比页面读取时的快照。曲目被其他客户端修改时，返回 409，提示刷新后重新操作。两端排序均核对完整顺序及歌曲集合；QQ 增删只比较集合，不修改顺序。
4. 同账号同歌单的保存请求在当前服务进程内串行保护，重复添加和移除不会重复写入。
5. 使用平台的单次增删或排序接口提交；写接口不自动重试。
6. 读回平台歌单，确认实际歌曲集合或顺序。读回不一致、超时或业务码失败均显示错误，前端重新读取列表，避免将未知结果显示为成功。

快照检查无法阻止其他官方客户端在“检查后、写入前”再次修改歌单；写后校验会提示差异。多进程部署需要共享锁，目前锁只覆盖单服务进程。

## 接口及来源

- 网易云：`POST /api/music/netease/playlist/edit`，调用项目已安装 SDK 的 `playlist_detail`、`playlist_tracks`、`song_order_update`。
- QQ：`POST /user/playlist/edit`，通过本人自建歌单清单和详情的 `owndir`、公开 ID、目录 ID 共同核实归属。歌曲 MID 在后端解析为数字 ID 和类型；调用 `music.musicasset.PlaylistDetailWrite` 的 `AddSonglist` / `DelSonglist` / `SeqSonglist`。详情刷新与排序校验统一使用 `CgiGetDiss` 有序分页读取。
- QQ 写请求采用签名加密 Web 通道，固定 HTTPS 网关、禁用重定向，检查外层、业务块和内部业务码。协议依赖固定版本的 [@jixun/qmweb-sign](https://github.com/jixunmoe/qmweb-sign)（MIT）；增删参数对照 [QQ 官网公开脚本](https://y.qq.com/ryqq/js/common.chunk.e536f9d2621979d755f5.js?max_age=2592000)。

请求体：`{ id, action, baseIds, trackId?, ids?, name?, baseName?, coverTrackId? }`。`action` 为 `add` / `remove` / `reorder` / `metadata`；`baseIds` 是页面加载到的完整歌曲标识，`ids` 是排序后的完整标识数组。资料编辑携带旧名称快照，封面歌曲须来自当前歌单。

## 验证

运行 `npm run check:playlist`、`node scripts/check-platform-library.cjs`、`npm run typecheck`、`npm run build`。

自动化使用隔离模拟账号，覆盖无登录、非本人歌单、快照冲突、非法参数、增删、排序、幂等、并发、业务失败和读回不一致。QQ 签名通道已做匿名公开歌单读取检查；这不等同于真实账号写入验收。

实际联调请使用自己创建的测试歌单：添加一首歌后在官方客户端刷新确认，移除后再次确认；两端另检查上移和下移。再在官方客户端修改歌单，确认旧页面保存时提示冲突。不要通过自动化修改用户已有私人歌单来代替验收。当前浏览器连接服务不可用，页面美观、字体、尺寸、对齐和点击交互尚未完成实际验收。
