# 年度榜单拖拽、本地封面和反向导入

更新日期：2026-11-11。

## 本地封面

“编辑歌单”提供本地文件选择和预览，支持 10 MB 内 JPEG、PNG、WebP。浏览器居中裁成正方形，最长边限制 1000 像素，转为 JPEG；提交体内图片不超过 2 MB。两端 JSON 接收上限为 4 MB，并在服务器重新检查 Data URL、Base64、大小和 JPEG／PNG 文件签名。

QQ 官网公开编辑页的 `handlePicUploadCgi` 先生成 `canvas.toDataURL("image/jpeg", quality)`，调用：

```text
module: music.filesys.FileSystem
method: PutImage
param: { BusID: "songlist", FileName: "<uin>_<timestamp>.jpg", Data: "data:image/jpeg;base64,..." }
result: data.URL
```

来源：[官网编辑页脚本](https://y.qq.com/ryqq/js/playlist_edit.chunk.2725441057c73cad7c10.js?max_age=2592000)，同一页面图像工具的裁剪结果为完整 Data URL，不能擅自去掉前缀。服务器只将平台返回的有效 QQ 图片地址交给 `EditPlaylist`。网易云复用已安装 SDK 的 `playlist_cover_update` 与内存文件对象，不把图片写入本地登录态文件或仓库。

## 年度榜单拖拽

整条排名项目可鼠标拖动，移动超过 6 像素才开始；松手后更新顺序及 `rank`，分数、评价、封面均保留。评分／不评分模式一致。按钮不会启动拖拽，普通封面点击保持预览功能。触屏从排名数字或封面区域拖拽，文字区域可滚动。靠近视口边缘自动滚动，Escape 或 pointer cancel 取消；Alt＋上下方向键可调整聚焦条目。外部修改会使进行中的旧拖拽失效，避免覆盖数据。

## 榜单导入现有平台歌单

在年度单曲榜／专辑榜选择“导入平台歌单”，选择 QQ 或网易云以及本人创建的普通歌单，先“匹配并预览”，再确认导入。没有歌单时，先在原平台创建后刷新列表。本次不自动创建歌单。

- 单曲：在目标平台查找同名、同歌手的歌曲，不取任意搜索首条。预览会显示命中的歌曲、歌手和专辑，供确认版本。
- 专辑：按名称和歌手匹配目标平台专辑，取其曲目列表第一首。当前接口没有可核实的单曲收藏量，未将播放热度或评论量冒充收藏量，也不使用用户上传的榜单封面来猜专辑身份。
- 不匹配的条目单独显示原因，确认操作只导入匹配成功的条目。
- 保留目标歌单现有顺序；已存在和榜单重复歌曲跳过。新增歌曲按榜单顺序追加，必要时调用一次完整排序，并读回核对。
- 每次增歌使用平台最新返回的完整 ID 快照，所有写入仍受归属、快照冲突和同歌单锁校验保护。中途失败停止后续写入，显示已确认添加数量；不自动清空、删除或回滚原歌单。超时的最后一次操作可能已生效，需先刷新目标平台检查。

## 验证范围

`npm run check:playlist` 覆盖两端上传格式、大小、协议参数和读回，年度榜单拖拽阈值／预览／松手提交／取消／外部编辑保护，以及反向导入匹配、专辑第一首、去重、保留已有歌曲、排序和部分失败。`npm run check:ranking` 验证既有榜单保存、历史、评分与编辑流程。

当前会话没有可用的浏览器控制工具，因此实际字体、尺寸、对齐、鼠标／触屏体验与真实账号写入仍需页面验收；隔离模拟测试不等同于平台实号验收。
