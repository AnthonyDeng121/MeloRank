# QQ 歌单歌曲排序参数核对

核对日期：2026-11-09。目标：在 MeloRank 内调整本人歌单曲目顺序并同步到 QQ 音乐。

## 官方客户端中的直接依据

检查本机已安装的 QQMusic 21.81 协议文件，仅做静态读取，未修改或注入客户端进程。

- 文件：`QQMusic_Protocol.dll`，1,959,072 字节。
- SHA-256：`053BC1F2BCBFB68C9FEF1EEEB58A31046EA888D19B63AF8E1C1A57925D396948`。
- 32 位 PE，ImageBase `0x10000000`。
- 方法字符串初始化 `0x1000c7e1` 将 `music.musicasset.PlaylistDetailWrite.SeqSonglist` 关联到 `0x10197740`。
- 请求序列化函数 `0x100ee0bf` 将请求关联到同一个 `0x10197740`。
- 该函数按以下位置写 JSON 字段：`0x100ee11f` 写 `dirId`；`0x100ee172` 写 `tid`；循环中 `0x100ee1ec` 写 `songType`、`0x100ee21e` 写 `songId`；`0x100ee23d` 将每项追加到 `v_songPair`。

据此确认请求结构，而非仅从方法名称猜测：

```json
{
  "module": "music.musicasset.PlaylistDetailWrite",
  "method": "SeqSonglist",
  "param": {
    "dirId": 1,
    "tid": 9,
    "v_songPair": [
      { "songType": 0, "songId": 3 },
      { "songType": 0, "songId": 1 }
    ]
  }
}
```

示例 ID 是测试占位值。服务端依据页面提交的 MID 顺序，从重新读取的歌单中映射真实歌曲 ID 和类型；目录 ID 由当前账号的自建歌单清单确定。

## 实现与验证边界

前端为 QQ 开放上移和下移；后端要求目标顺序包含全部歌曲且无重复，比较完整旧顺序以拒绝过期页面，通过现有签名 Web 通道提交后，再逐项核对读回顺序。未采用删光重加，也未在客户端本地排序后假报平台成功。

自动化覆盖参数映射、缺项/重复/外来歌曲、旧顺序冲突、不变顺序幂等、并发锁、平台返回同集合但错误顺序，以及详情分页保持平台顺序。

实号验证尝试在独立私密测试歌单进行，但当前本地登录态在创建测试歌单时收到外层 `0`、业务块 `1000`。测试歌单未创建，读取清单确认没有遗留同名测试歌单，未修改已有歌单。因此本次不能宣称真实账号排序成功；重新扫码登录后仍需确认该请求在 Web 通道中的真实写入和顺序读回。模拟测试通过不替代这一检查。

浏览器连接服务不可用，实际字体、尺寸、对齐和点击交互尚待页面验收。
