# 与 Netlify 部署版的对照检查

日期：2026-10-25（北京时间）。基准：https://melorank.netlify.app/ 。本次只修改本地代码，未 commit、未 push、未重新部署 Netlify。

## 本次目标

以实际部署版本为基准，修正回退后的页面、交互、数据和样式差异，并留下可重复的验证方法。原始 TSX 源码与部署构建文件不是同一种文件，本报告不声称恢复了原始变量名、注释或 Git 历史。

## 方法

1. 读取当前线上页面及公开 JS/CSS，使用语法树读取构建代码，未执行下载的 JavaScript。
2. 将构建后的本地主要组件与线上组件做绑定名归一化后的语法对照，保留属性名、字面量、运算符和语法结构。
3. 比较全部 35 首歌曲、83 张 Album、14 张 EP 的完整数据；校验 15 张本地图片的 SHA-256。
4. 比较应用 CSS 声明及六个宽度下的声明顺序，再用浏览器检查真实计算样式。仅比较规则集合会漏掉覆盖顺序问题，本次手机封面差异就是这样发现的。
5. 对真实页面处理函数做隔离的内存存储测试，不触碰用户浏览器已有的历史榜单。

## 如何复查

```powershell
npm run typecheck
npm run check:ranking
npm run check:deployed
```

最后一条会重新构建、读取当前 Netlify 公开部署资源、检查图片并写入静态报告。线上重新部署后基准可能改变；报告中记录了实际资源 URL 和 SHA-256。

静态语法和 CSS 对照是较强的证据，但不等价于所有浏览器、账号、数据和网络条件下的完整运行证明。结论应表述为“已验证范围内与当前部署版对齐”，不应表述为“所有功能 100% 一模一样”。

## 可学习、汇报的要点

- 回退到某个 commit 不代表回到了线上实际部署的源码，尤其手动上传 dist 的部署没有对应提交保证。
- 展示榜单与编辑榜单的路由职责要区分；入口存在不代表数据页面已恢复。
- 除内容外，还应检查空状态、默认值、接口参数、交互状态及 CSS 声明顺序。
- 使用等价初始状态和相同视口进行页面对照，避免将焦点、悬停、滚动和动画差异误判为代码差异。
- 将静态对照、隔离行为测试和真实浏览器验收分开记录，明确外部服务和权限造成的验证边界。
